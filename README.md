# bili-lottery

B 站「双关注 + 转发」抽奖脚本。一次性工具：抓取某条动态的全部转发者，
验证他们是否同时关注了两个指定 UP 主，然后抽奖并给出可复现的结果。

支持多档奖项（一等奖 / 二等奖），**同一次洗牌切分，三档天然不重叠**。
抽奖动态链接和两个 UP 主 UID 固定写在脚本顶部，日常只需传中奖名额和 seed。

## 为什么需要它

B 站官方「互动抽奖」只能要求「关注我 + 转发」，**无法强制要求关注第三方 UP 主**。
所以「同时关注 A 和 B」这个条件只能自己验证。

## 复现性

抽奖结果 100% 可复现：

1. 合格名单按 UID 排序
2. `sha256(seed + 名单)` 生成随机种子
3. 用该种子做 Fisher-Yates 洗牌，取前 N

多档奖项不重叠的做法：**只洗一次牌**，按顺序切片——
先切一等奖，紧接着切二等奖，再切备选。同一元素不可能落在两档里。

同样的名单 + 同样的 seed，任何人跑出完全相同的结果。

抓取环节依赖当时的转发列表快照 —— 转发会持续增长，重新抓名单就会变。
因此**定案必须以冻结的名单 CSV 为准**。

### 公示时用哪个哈希

有两个哈希，别用错：

- **名单摘要 sha256**（脚本输出的 `名单摘要 sha256`）— **用这个公示**。
  它只由「排序后的合格 UID 列表」算出，跨多次抓取保持稳定。
- **文件 sha256** — 仅供参考。B 站转发列表只给相对时间（「40分钟前」），
  两次抓取会差几分钟，文件字节必然不同，拿它公示会被质疑。

实测：相隔 12 分钟独立抓取两次，CSV 文件哈希不同（仅因为相对时间变了），
但 UID 集合、关注状态、名单摘要、中奖者全部一致。

## 安装

```bash
pip install requests
```

## 配置

脚本顶部写死，要改直接改这几行：

```python
DYNAMIC_URL = "https://www.bilibili.com/opus/1261303758808154120"
UP_A_UID = "297667433"
UP_B_UID = "3747571612781876"
BACKUP_N = 3          # 备选人数
```

## 用法

### 抓取并抽奖

```bash
python3 bili_lottery.py <一等奖人数> <二等奖人数> <seed>
```

示例（一等奖 1 名 + 二等奖 3 名）：

```bash
python3 bili_lottery.py 1 3 3697
```

输出：

- 屏幕：一等奖 / 二等奖 / 备选 + 名单摘要
- 文件：`lottery_<动态ID>_all.csv`，含每个人对 A/B 的关注状态、关注数、是否合格

### 离线复算（不需要 Cookie、不需要联网）

```bash
python3 bili_lottery.py --replay lottery_<动态ID>_all.csv <一等奖人数> <二等奖人数> <seed>
```

会重算并输出同样格式的结果，供第三方独立验证。

## 原理

| 步骤 | 接口 |
| --- | --- |
| 动态详情 / 转发数 | `/x/polymer/web-dynamic/v1/detail` |
| 转发列表 | `/x/polymer/web-dynamic/v1/detail/forward` |
| 用户关注列表 | `/x/relation/followings?vmid=` |
| WBI 签名密钥 | `/x/web-interface/nav` |
| 设备指纹 | `/x/frontend/finger/spi` |

旧版 `api.vc.bilibili.com` 接口已整体下线，本项目用新版 polymer 接口。

## 已知限制

- **隐私账号无法验证**：对方关闭关注列表可见性时接口返回 `code 22115`，查不到关注关系。
  只能排除、要求对方提供截图补验，或放宽处理。
- **只能查当前状态**：无法验证「转发那一刻是否已关注」，也防不住抽完就取关。
  领奖时建议再复核一次。
- **同一个人可能转发多次**：按 UID 去重，只保留一条。
- 接口是逆向得到的，B 站改版后可能失效。

## 公平性提醒

`seed` 决定谁中奖。如果发起人能自己挑 seed，理论上可以反复试值直到抽中心仪的人。
**结果可复现 ≠ 公平**。

正规做法：用发起人无法提前预知的公开数据作为 seed，例如开奖时刻的比特币区块哈希、
指定期号的双色球号码。这样事先算不出来，事后谁都能验。
